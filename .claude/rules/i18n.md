# User-facing strings

Fluent syntax, plural selectors and worked examples:
`agent-docs/conventions/i18n-conventions.md`.

## Where strings live

- `src/i18n/strings.ftl` (US English) is the only string file to edit.
- Never edit `src/i18n/l10n/` — those files come from Crowdin and your edits are overwritten.

## Using them

- All user-facing text goes through `t()` from `useTranslation()`. ESLint's i18next rule
  catches literals.
- Use `<Trans>` when the string contains JSX; interpolating a component into `t()` does not
  work.
- Prefer separate strings over a variable. `{ $count }` and similar force every translator to
  guess at grammar the source language hides.
- Pluralize with a selector, never by concatenating:
  `{ $count } { $count -> [one] observation *[other] observations }`.

## Naming keys

- Kebab-case. The key should read as the content, and the content stays under 100 characters.
- **Change the key when the content changes.** Reusing a key for a new meaning ships the old
  translation to 40 locales, and nothing catches it.
- Disambiguate same-word keys with a double dash: `Unknown--rank`, `Unknown--taxon`.
- Add a comment above the string when a translator would need context to get it right.
